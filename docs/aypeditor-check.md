1. Scrolled-out AYP buttons were registered for automation at rects under the toolbar: `ui.click {"id":"ayp.item.clip.group"}`
   pressed Làm lại (Redo).
2. Xoá chữ chọn (lift / extract) always failed ("`from` (word index) is required"): it ignored the words picked in the Text panel.
3. Selecting a TTS narration added a classic Text to Speech tab beside Program, and the layout autosave kept it in the AYP
   workspace for good. Automatic reveals (narration selected, caption double-click, Show Transcript, Reveal in Project) now
   open the AYP tab that embeds the panel; a deliberate Window ▸ panel or `ui.panel.show` still opens the classic panel.
4. Xoá từ đệm used the engine's English-only filler list (um, uh…): it could never remove a Vietnamese "ờ / ừm". It now also
   knows ờm, ừm, ừmm, ùm, ưm, hừm, hm.
5. Xoá khoảng lặng / Xoá từ đệm that found nothing showed nothing (looked dead): now "Không tìm thấy chỗ nào để xoá".
6. Chuẩn hoá âm lượng failed on every untagged clip ("no clips with an audio type"): it now tags the selection Dialogue first.
7. A failed click's "Chưa làm được: …" stayed next to the next, working result (library, toolbar and Tìm lệnh…).
8. Two English reasons leaked (ducking without a Music clip, multicam cut without a multicam clip) and "select clips first"
   was shown as "Chưa làm được: Chưa làm được: …".
9. No button made a transcript, and the Text panel's Transcribe uses the shared prefs (whisper-base, not downloaded, and
   English): "Chép lời (tiếng Việt)" now comes first in Cắt bằng chữ and Phụ đề (large-v3-turbo, vi); row 1 used it.
10. Bắt đầu ghi âm lời recorded on A1 over the clip's own sound and, run bare, rolled no playback: it now uses the Timeline's
    record toggle on the first empty audio track (a new one when none is empty). Recording itself is still MANUAL here.

## Still not right / not verified (not hidden)

- **Ghi âm lời thoại** was not run (microphone); the track choice and the record toggle are covered by a UI test with the
  synthetic input.
- **Chép lời** runs on the UI thread, as FilmCraft's own Transcribe does: the window does not respond until it ends (about
  55 s for 60 s of speech, so about 4 minutes for a 4-minute clip).
- **Mặt nạ bám theo vật** follows one shot. Run to the end of the clip across a shot change it stops with "lost track …: not
  enough detail inside the mask" (FilmCraft tracker); the row trims the clip to one shot (10–40 s) and puts the mask on the face.
- **Chuẩn hoá âm lượng** matches Dialogue to −23 LUFS (FilmCraft's broadcast default), quieter than social-video practice.
- **Khớp màu** refuses a reference frame inside the same clip; it needs a second shot (a cut) first.
- **Duyệt góp ý** opens the page in the default browser; the browser then covers the editor, and while it is covered
  synthetic `ui.click` requests reply ok but do nothing (`ui.screenshot` times out) until `ui.focus`.
- Effects (skin smooth, blur, Warp Stabilizer, Auto Reframe, Ultra Key, flip, crop) are verified as added to the clip with a
  history step; their rendered look was not judged frame by frame, and Warp Stabilizer / Auto Reframe started no analysis job.
- PASS(panel) / PASS(ai) / PASS(dialog) / PASS(cmd) rows ran the command with chosen params, not a click on the embedded
  panel's controls; the two PASS(no-op click) rows clicked a button that found nothing to remove on this clip.
